## Find buttons inside submenus too

The selection includes **38 dialog states and 54 concrete menu paths**. Search menu paths to find deeper levels such as **Setup → Software Management → Advanced Options → Package Manager** or **Setup → System → Storage Devices → Device Manager**. Then choose the open subdialog where needed: **Mount Points**, **Prepare Device Action**, **Server Credentials** or **Edit Recording Timer**, for example.

Scanning has separate **running** and **results** states: OK selects a discovered service only after completion. In **Plugin Browser: Edit Mode**, red resets ordering; in normal plugin selection it opens removal. In **DNS Settings**, yellow moves a server; in **Set Root Password**, it generates a random password. The shared Setup table cannot describe these differences on its own.

**Context Menu / Further Choices** describes the next level after MENU, for example in Network Overview. This ChoiceBox creates digit and colour shortcuts directly from its entries. Follow the marker beside each entry; red does not necessarily mean cancel. Menu paths assume the normal list-style menu. Setup level, hardware, skin and installed plugins determine which entries your receiver actually displays.

## Global C/C++ functions: hold 0 and OSD

**Hold 0** to pause automatic OSD hiding. **Hold 0 again** to resume it. This requires **Menu → Setup → Usage & GUI → OSD Settings → Automatically hide OSD** to be enabled and hardware support for OSD alpha. The temporary pause ends at the next GUI restart at the latest; it does not disable the saved setting.

This function is implemented directly in `eAVControl::handleOSDKey()` and runs **before normal screen ActionMaps**. The finder therefore includes it in every reviewed screen, including input fields and confirmation dialogs. Searching only for `flags="l"` in `keymap.xml` would miss it.

With OSD auto-hide enabled, these additional rules apply:

- **OSD visible, short 0:** The normal 0 action is replayed only on release, such as entering a digit or recalling the previous channel.
- **Long 0:** Only the OSD pause is toggled. The short 0 action is suppressed, so this must not zap or enter a digit.
- **OSD already hidden:** The first button only restores the display. Repeat, long and release events belonging to that wake-up press are consumed too. Press again to perform the screen action. The 0 button additionally has the special long-press behaviour described above.

Hiding the OSD does not close a dialog or stop background work. Newly opened dialogs restore visibility. Source evidence: [native OSD key handling](https://github.com/openatv/enigma2/blob/6588fdc15f040293d212dc15ec63194e82c8269f/lib/driver/avcontrol.cpp#L972), [precedence over ActionMaps](https://github.com/openatv/enigma2/blob/6588fdc15f040293d212dc15ec63194e82c8269f/lib/actions/action.cpp#L219) and [setting and pause notification](https://github.com/openatv/enigma2/blob/6588fdc15f040293d212dc15ec63194e82c8269f/lib/python/Components/AVSwitch.py#L274).

## Find the buttons on this remote

- **Receiver POWER** is at the top right. The red button at the top left is a different control and has no Enigma2 assignment in the reviewed remote XML.
- **HELP** is at the right end of the symbol row directly below POWER. On this model Enigma2 receives it as **INFO**. During live TV it opens the configured INFO view, rather than automatically opening general button help.
- **EPG** is below the navigation ring on the left. The remote XML calls its original code `KEY_INFO`; the model-specific remapping changes it to `KEY_EPG`. The finder preserves the visible label **EPG**.
- **PVR** is above the ring on the left, **MENU** on the right. **EXIT** is below the ring on the right.
- **CH+ / CH−** are below the ring on the right. Source code and other guides may call them **BOUQUET+ / BOUQUET−**. Their function depends on the screen.
- **TIMER** is between the lower volume/channel controls, just above the playback row. The arrows beside **0** are separate buttons from both the navigation ring and the rewind/fast-forward buttons.

The visible **AV** and **red POWER at top left** controls are included without inventing an Enigma2 function. The remote catalogue does not assign receiver keycodes to them. Any configured control of a television is separate.

## Press, release and hold

| Finder label | Meaning |
| --- | --- |
| On press | The action starts as you press down. It can also run before a later long press is detected. |
| On short release | Press briefly, then release. Many colour and Infobar buttons respond at this point. |
| Long press | Keep holding until the long action is recognised. There is no single duration in seconds for every device and setting. |
| Repeat while held | An action such as navigation or volume adjustment repeats. This is different from a long-press event. |
| Release after long press | Finishes a long operation, e.g. restoring the normal volume step size. |

The input dispatcher distinguishes a short release from **Stop after a recognised long press**. Releasing after a long press therefore does not automatically run the short release action as well. Actions already triggered on press or repeat may still have run. Two short presses are different again: **MENU → MENU** first opens the main menu and then its OSD settings.

**Long-press detection** is also centralized in C++: `main/enigma.cpp` generates it from repeated events for the same button. The handset and repeat settings therefore affect how long you need to hold. **Remote Control Button Settings → Long press emulation with button** can assign a prefix button: press it, then press the target button within ten seconds on the same remote. Enigma2 generates a long press for that target. The prefix button loses its usual function because this global handler consumes it first. The finder assumes emulation is disabled, as in the default configuration. Logical keycodes apply on this VU+ remote: printed HELP sends INFO, printed EPG sends EPG. [C++ detection and emulation](https://github.com/openatv/enigma2/blob/6588fdc15f040293d212dc15ec63194e82c8269f/main/enigma.cpp#L72).

## One button, different jobs

**MENU** opens the main menu during live TV, the context menu in the channel list, settings in graphical EPG and file/folder actions in recordings. In a Setup selection field MENU opens the available choices; this action may be disabled for other field types.

**PVR** during live TV opens recordings on a short press and MediaPlayer on a long press, if installed. In the native recordings list it opens directory selection. In an editable Setup text field or the on-screen keyboard, PVR can instead clear the text. Check the current screen before pressing it.

**HELP (internally INFO)** opens event information during TV, a timer log in the timer overview, and switches insert/overwrite mode in the on-screen keyboard. Select the relevant screen in the finder to see the matching function.

Colour buttons also have no permanent meaning. Green often saves settings, adds a timer in the timer overview, and accepts text in the on-screen keyboard. Several colour-button actions in graphical EPG and recordings are configurable. Follow the current on-screen label and your receiver’s settings.

## Why my receiver behaves differently

The finder describes **standard keymap.xml** and screen states verified against source code. It does not read your receiver settings. Differences can come from:

- **Custom hotkeys** or **Menu → Setup → Usage & GUI → Remote Control Button Settings**.
- Another keymap, alternative navigation or extra plugins. EMC is a separate recordings screen and is not described by the MovieSelection profile.
- Another focus or subdialog: EPG bouquet selection, channel-list editing/moving, a timer editor, confirmation prompts, PiP or active timeshift.
- Another handset or custom input-device remapping.

Volume, mute and POWER have global handlers. A screen can intercept buttons or block actions, however. Setup blocks standby and the long POWER action, for example. “Global” therefore does not guarantee availability in every state.

**No separate action recorded** describes coverage of this state; it does not promise that a plugin can never use the button. See [hotkey configuration](../../erste-schritte/farbtasten-langdruck/), [remote button settings](../../einstellungen/referenz/remotebutton/), [input devices](../eingabegeraete/) and the [long-press directory](../../anhaenge/langtasten/) for more options.

## Where the mapping comes from

This prototype connects four layers: **model → remote picture and button position → remapped keycode → action in the active screen**. For vuduo4klite, `configure.ac` enables `KEY_INFO_TO_KEY_EPG` and `KEY_HELP_TO_KEY_INFO`, among others. `lib/driver/rcinput.cpp` applies them in a defined order: HELP becomes INFO, but is not subsequently changed into EPG. An active custom remap table follows a separate processing path.

`data/keymap.xml` supplies event flags and action names. Native C/C++ handlers, dynamically generated Python assignments and native list navigation also contribute. ActionMaps, priorities, focus, `setEnabled()` and handlers determine which screen actions apply. `data/menu.xml` supplies nested menu paths; German labels come from `po/de.po`. The finder uses reviewed profiles and shares tables only for controls verified to be common. Each expandable technical mapping links to the relevant source snapshot.
