**Menu → Setup → Usage & GUI → Keyboard Settings** selects the mapping for a connected keyboard. **QWERTY** and **QWERTZ**, for example, differ in Y/Z and many punctuation keys. Match the physical keyboard, not necessarily the menu language.

1. Connect the keyboard and check detection under [Input Devices](../eingabegeraete/).
2. Select the matching available layout and press Green/Save.
3. When changed, the dialog loads the layout for a test and asks whether it works. Without confirmation this test falls back after 30 seconds.
4. In a suitable text field check Y/Z, accented letters, `@`, `/`, `:`, `-` and digits. Do not type passwords into a visible test field.

This selection already has a [Keyboard reference](../../einstellungen/referenz/keyboard/). The default displayed in a screenshot can vary with the active language; your physical keyboard determines the appropriate choice.

## On-screen keyboard and handset entry

Depending on the dialog, text fields offer an on-screen keyboard, often through the displayed **TEXT**/keyboard-symbol action. Colour keys, shift and available characters are shown there. Some fields support repeated number-key presses similar to older mobile phones. Numeric/IP fields behave differently from filename fields.

Try cursor movement, deletion and insertion in a harmless field first. For long text, **Customize System Settings → Input scroll position** controls the visible portion. Configure repeat timing under [Input Devices](../eingabegeraete/).

An external layout does not change every plugin action or automatically replace every on-screen keyboard layout. Missing font characters are a skin/fallback-font issue, not something solved by exchanging QWERTY and QWERTZ.
