## Source first, then a visible result

The source revision pinned in the [API reference](../api/) remains the technical reference. Each chapter distinguishes production screen contracts from the lab's explicit fixture data. A fixture is a small controlled input: it makes an example repeatable without tuning a channel, writing a bouquet or requiring a live broadcast.

The nine additional native OSD images use the same downloadable **Handbook Skin Lab** as the foundations. The plugin does not select a new main skin. The examples are English in both handbook editions, and the automatic translation menu can translate their explanations.

## Keep these three boundaries clear

- **Screen versus component:** the Python screen owns the objects; XML styles the objects that exist.
- **Source versus presentation:** a source exposes data and changes; a converter derives a particular value; a renderer paints it.
- **General XML versus specialised templates:** a `ServiceList` row template uses its own parser. Its fields are not arbitrary screen widgets.
